P1 Debugging — Perbaikan Bug Berat 1,3 kg → 2 kg

Unit Kompetensi
J.620100.025.02
Durasi
30 menit
Tingkat
Mudah

🎯 Tujuan

Memperbaiki bug perhitungan berat yang dibulatkan ke bawah (floor). Bug asli: 1,3 kg ditagih 1 kg (kerugian Rp 2.700/paket).

📖 Konteks Bug

InputHasil Lama (Bug)Hasil BenarKerugian
1,3 kg1 kg → Rp 9.0002 kg → Rp 18.000Rp 9.000
2,7 kg2 kg → Rp 18.0003 kg → Rp 27.000Rp 9.000
4,1 kg4 kg → Rp 36.0005 kg → Rp 45.000Rp 9.000
⚠️ Dampak Bisnis Dengan 15.000 paket/hari dan asumsi 30% paket beratnya desimal, kerugian = 15.000 × 0,3 × Rp 9.000 = Rp 40.500.000/hari.

🔍 Langkah Praktikum

  1. Buka Service OngkirService

    notepad app\Services\OngkirService.php

  2. Amati Method hitungBeratTagih()

    public function hitungBeratTagih(float $beratAktual, ?float $p = null, ?float $l = null, ?float $t = null): float
{
    $beratVolumetrik = 0;
    if ($p && $l && $t) {
        $beratVolumetrik = ($p * $l * $t) / 6000;
    }
    $beratMaks = max($beratAktual, $beratVolumetrik);
    return (float) ceil($beratMaks);  // ← KUNCI: ceil() bukan floor()
}

    Kata kunci perbaikan: ceil() (pembulatan ke atas), bukan floor() atau (int).

  3. Buat Test Script untuk Verifikasi

    php artisan tinker

    Di dalam Tinker, jalankan:

    $s = new App\Services\OngkirService();
echo $s->hitungBeratTagih(1.3);  // Output: 2
echo $s->hitungBeratTagih(2.7);  // Output: 3
echo $s->hitungBeratTagih(4.1);  // Output: 5
echo $s->hitungBeratTagih(1.0);  // Output: 1
echo $s->hitungBeratTagih(0.5);  // Output: 1

    Ketik exit untuk keluar Tinker.

  4. Test Volumetrik

    Test berat volumetrik (dimensi lebih dominan):

    // 3 kg aktual, dimensi 40×30×20 cm → volumetrik = 4 kg
echo $s->hitungBeratTagih(3, 40, 30, 20);  // Output: 4

// 2 kg aktual, dimensi 10×10×10 cm → volumetrik = 0.17 kg
echo $s->hitungBeratTagih(2, 10, 10, 10);  // Output: 2

  5. Simpan Output Bukti

    php artisan tinker > bukti-praktikum\p1-debugging.txt 2>&1
REM Ketik kode verifikasi di atas, lalu exit
✅ Output yang Diharapkan Semua berat aktual dan volumetrik dibulatkan ke atas dengan benar. Bukti tersimpan di bukti-praktikum/p1-debugging.txt.
💡 Konsistensi Format Nomor Resi Model Resi::buatNomorResi() menghasilkan format SLC-YYYYMMDD-XXXX. Pastikan factory juga pakai format yang sama: 
'nomor_resi' => 'SLC-' . now()->format('Ymd') . '-' . str_pad($seq, 4, '0', STR_PAD_LEFT),
Ini penting untuk konsistensi data dummy vs data production.

P2 Profiling — Debugbar & N+1 Query

Unit Kompetensi
J.620100.031.01
Durasi
45 menit
Tingkat
Menengah

🎯 Tujuan

Mengukur performa query database dan mengeliminasi N+1 Query Problem menggunakan Laravel Debugbar.

📖 N+1 Query Problem

SkenarioJumlah QueryDurasi
Tanpa eager loading (N+1)21 query350–500 ms
Dengan with()3 query80–110 ms
Dengan with() + indeks3 query< 60 ms

🔍 Langkah Praktikum

  1. Install Laravel Debugbar

    composer require barryvdh/laravel-debugbar --dev

    Debugbar hanya untuk development (--dev), tidak akan ikut ke production.

  2. Buka Halaman Daftar Resi

    Di browser, buka http://localhost:8000/resi dan perhatikan Debugbar di bagian bawah. Catat:

    • Queries — jumlah query
    • Timeline — durasi eksekusi

  3. Cek Kode Saat Ini (Sudah Benar)

    Buka app\Http\Controllers\ResiController.php:

    public function index(Request $request)
{
    $resi = Resi::with(['pelanggan', 'cabangAsal', 'cabangTujuan', 'layanan'])  // ← EAGER LOADING
        ->cari($request->query('q'))
        ->status($request->query('status'))
        ->orderByDesc('created_at')
        ->paginate(15)
        ->withQueryString();

    return view('resi.index', compact('resi'));
}
    ✅ Kode Ini Sudah Benar with(['pelanggan', 'cabangAsal', ...]) mencegah N+1.

  4. Simulasi N+1 (Bandingkan)

    Buat controller temporary untuk simulasi. Buka routes/web.php, tambahkan:

    Route::get('/debug-nplus1', function () {
    // TANPA eager loading — akan jadi N+1
    $resi = App\Models\Resi::limit(10)->get();

    foreach ($resi as $r) {
        echo $r->pelanggan->nama . '
    ';  // Setiap iterasi query ke DB
    }

    return 'Lihat Debugbar di bawah — perhatikan jumlah query';
});

    Buka http://localhost:8000/debug-nplus1. Perhatikan Debugbar menunjukkan 11 query (1 untuk resi + 10 untuk pelanggan).

    ⚠️ Kalau Query Cuma 2, Bukan 11? Berarti data di tabel resi kamu cuma 1 baris. Generate dulu 10 data: 
    php artisan tinker
App\Models\Resi::factory(10)->create();
exit
    Kalau muncul error Field 'X' doesn't have a default value, berarti ada kolom NOT NULL yang belum diisi di factory. Lihat section Troubleshooting.

  5. Perbaiki dengan Eager Loading

    Route::get('/debug-nplus1-fixed', function () {
    // DENGAN eager loading — hanya 2 query
    $resi = App\Models\Resi::with('pelanggan')->limit(10)->get();

    foreach ($resi as $r) {
        echo $r->pelanggan->nama . '
    ';
    }

    return 'Lihat Debugbar — hanya 2 query!';
});

    Buka http://localhost:8000/debug-nplus1-fixed. Debugbar akan menunjukkan 2 query.

  6. Cek Rencana Eksekusi (EXPLAIN)

    ❌ JANGAN tulis SQL mentah langsung di Tinker! Kalau kamu tulis EXPLAIN SELECT ... langsung di Tinker, akan error: Parse error: Syntax error, unexpected T_STRING.

    Yang benar, bungkus dengan DB::select():

    // Di Tinker
DB::select("EXPLAIN SELECT * FROM resi WHERE nomor_resi LIKE 'SLC%'");

    Atau lewat MySQL CLI langsung:

    EXPLAIN SELECT * FROM resi WHERE nomor_resi LIKE 'SLC%';

    Perhatikan kolom type:

    • ALL = full table scan (buruk)
    • ref / range = pakai indeks (baik)
    💡 Catatan EXPLAIN Kalau data di tabel masih sedikit (< 1000 baris), MySQL akan tetap full scan karena lebih cepat. Untuk melihat perbedaan index, generate 10.000 data dulu: 
    App\Models\Resi::factory(10000)->create();
    Lalu bandingkan EXPLAIN sebelum dan sesudah ALTER TABLE resi ADD INDEX idx_nomor (nomor_resi).

  7. Simpan Screenshot Debugbar

    Screenshot halaman /resi dengan Debugbar terbuka. Simpan sebagai bukti-praktikum/p2-debugbar.png.

✅ Output yang Diharapkan
  • Screenshot Debugbar: 3 query, durasi < 100ms
  • Bukti perbandingan: N+1 = 11 query vs Eager = 2 query
  • Hasil EXPLAIN: type=ref (pakai indeks) setelah ada index

P3 Pengujian Integrasi — Feature Test PHPUnit

Unit Kompetensi
J.620100.034.02
Durasi
60 menit
Tingkat
Menengah

🎯 Tujuan

Menulis Feature Test untuk menguji alur end-to-end pembuatan resi: dari HTTP request → validasi → service → database.

📖 Perbedaan Unit vs Feature Test

AspekUnit TestFeature Test
Cakupan1 method1 alur fitur lengkap
HTTP RequestTidakYa ($this->post())
DatabaseTidak (mock)Ya (refresh)
KecepatanSangat cepatLebih lambat
ContohTest ceil(1.3) == 2Test POST /resi → tersimpan
⚠️ PENTING — Baca Dulu Sebelum Mulai Banyak praktikan gagal di praktikum ini karena 3 hal:
  1. Migration duplikat — ada 2 file migration yang sama-sama buat tabel cabang. Error: table "cabang" already exists.
  2. Copy-paste dari browser — menyisipkan karakter tak terlihat (BOM/smart quotes). Error: No tests found.
  3. Anotasi /** @test */ tidak terdeteksi di PHPUnit tertentu. Solusi: pakai prefix test_.
Solusi ada di Langkah 0, 1, dan 2 di bawah.

🔍 Langkah Praktikum

  1. Langkah 0 — Cek Migration Duplikat (WAJIB)

    Sebelum bikin test, pastikan tidak ada migration duplikat. Jalankan:

    findstr /S /I "Schema::create" database\migrations\*.php

    Perhatikan output. Kalau ada 2 file berbeda yang sama-sama berisi Schema::create('cabang', ...), itu penyebab error table "cabang" already exists.

    ❌ Kalau Ada Duplikat Hapus file migration yang duplikat (biasanya yang lebih baru), lalu jalankan:
    php artisan migrate:fresh

  2. Langkah 1 — Buat File Feature Test

    php artisan make:test ResiFeatureTest

    File akan dibuat di tests/Feature/ResiFeatureTest.php.

  3. Langkah 2 — Isi Test Case (Ketik Manual, JANGAN Copy-Paste)

    ⚠️ JANGAN copy-paste dari browser! Browser sering menyisipkan karakter tak terlihat yang membuat PHPUnit tidak bisa membaca file. Ketik ulang secara manual di VS Code.

    Langkah 2a — Test Minimal Dulu (Verifikasi Deteksi)

    Isi file dengan versi paling minimal ini dulu:

    <?php

namespace Tests\Feature;

use Tests\TestCase;

class ResiFeatureTest extends TestCase
{
    public function test_sederhana(): void
    {
        $this->assertTrue(true);
    }
}

    Simpan, lalu jalankan:

    vendor\bin\phpunit --list-tests
    ✅ Verifikasi ResiFeatureTest::test_sederhana harus muncul di daftar. Kalau tidak muncul, jangan lanjut — ada masalah di environment (lihat Troubleshooting).

    Langkah 2b — Tambahkan Setup Lengkap

    Setelah test minimal terdeteksi, ganti isi file dengan versi lengkap. Gunakan prefix test_ pada nama method (jangan pakai anotasi /** @test */ — lebih universal):

    <?php

namespace Tests\Feature;

use App\Models\User;
use App\Models\Cabang;
use App\Models\Pelanggan;
use App\Models\Layanan;
use App\Models\Resi;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class ResiFeatureTest extends TestCase
{
    use RefreshDatabase;

    private function seedBasicData(): array
    {
        $user = User::factory()->create();

        $cabangAsal = Cabang::create([
            'kode' => 'JKT',
            'nama' => 'Jakarta',
            'kota' => 'Jakarta',
        ]);

        $cabangTujuan = Cabang::create([
            'kode' => 'BDG',
            'nama' => 'Bandung',
            'kota' => 'Bandung',
        ]);

        $pelanggan = Pelanggan::create([
            'nama' => 'PT Maju Jaya',
            'email' => 'maju@test.com',
            'telepon' => '081234567890',
            'is_member' => false,
        ]);

        $layanan = Layanan::create([
            'kode' => 'REG',
            'nama' => 'Reguler',
            'tarif_per_kg' => 9000,
            'min_kg' => 1,
            'asuransi_persen' => 0.2,
            'asuransi_min_nilai' => 1000000,
            'aktif' => true,
        ]);

        return compact('user', 'cabangAsal', 'cabangTujuan', 'pelanggan', 'layanan');
    }

    public function test_user_bisa_membuat_resi_baru(): void
    {
        $data = $this->seedBasicData();

        $response = $this->actingAs($data['user'])->post('/resi', [
            'pelanggan_id' => $data['pelanggan']->id,
            'cabang_asal_id' => $data['cabangAsal']->id,
            'cabang_tujuan_id' => $data['cabangTujuan']->id,
            'layanan_id' => $data['layanan']->id,
            'nama_penerima' => 'Budi Santoso',
            'telepon_penerima' => '089876543210',
            'alamat_penerima' => 'Jl. Merdeka No. 10, Bandung',
            'berat_aktual' => 1.3,
            'nilai_barang' => 0,
        ]);

        $response->assertRedirect();

        $this->assertDatabaseHas('resi', [
            'nama_penerima' => 'Budi Santoso',
            'berat_tagih' => 2,
        ]);

        $resi = Resi::first();
        $this->assertStringStartsWith('SLC-', $resi->nomor_resi);
    }

    public function test_resi_menolak_cabang_asal_dan_tujuan_yang_sama(): void
    {
        $data = $this->seedBasicData();

        $response = $this->actingAs($data['user'])->post('/resi', [
            'pelanggan_id' => $data['pelanggan']->id,
            'cabang_asal_id' => $data['cabangAsal']->id,
            'cabang_tujuan_id' => $data['cabangAsal']->id,
            'layanan_id' => $data['layanan']->id,
            'nama_penerima' => 'Test',
            'telepon_penerima' => '08123',
            'alamat_penerima' => 'Test',
            'berat_aktual' => 2,
            'nilai_barang' => 0,
        ]);

        $response->assertSessionHasErrors('cabang_tujuan_id');
        $this->assertDatabaseCount('resi', 0);
    }

    public function test_asuransi_dihitung_untuk_nilai_barang_diatas_1_juta(): void
    {
        $data = $this->seedBasicData();

        $this->actingAs($data['user'])->post('/resi', [
            'pelanggan_id' => $data['pelanggan']->id,
            'cabang_asal_id' => $data['cabangAsal']->id,
            'cabang_tujuan_id' => $data['cabangTujuan']->id,
            'layanan_id' => $data['layanan']->id,
            'nama_penerima' => 'Test',
            'telepon_penerima' => '08123',
            'alamat_penerima' => 'Test',
            'berat_aktual' => 2,
            'nilai_barang' => 2000000,
        ]);

        $resi = Resi::first();
        $this->assertEquals(4000, $resi->asuransi);
        $this->assertEquals(22000, $resi->total_biaya);
    }

    public function test_tracking_log_dibuat_otomatis_saat_resi_baru(): void
    {
        $data = $this->seedBasicData();

        $this->actingAs($data['user'])->post('/resi', [
            'pelanggan_id' => $data['pelanggan']->id,
            'cabang_asal_id' => $data['cabangAsal']->id,
            'cabang_tujuan_id' => $data['cabangTujuan']->id,
            'layanan_id' => $data['layanan']->id,
            'nama_penerima' => 'Test',
            'telepon_penerima' => '08123',
            'alamat_penerima' => 'Test',
            'berat_aktual' => 2,
            'nilai_barang' => 0,
        ]);

        $this->assertDatabaseHas('tracking_log', [
            'status' => 'pending',
            'lokasi' => 'Jakarta',
        ]);
    }
}

P4 Stress Test — Locust

Unit Kompetensi
J.620100.037.01
Durasi
60 menit
Tingkat
Sulit

🎯 Tujuan

Menemukan titik patah (breaking point) aplikasi SiLacak saat diakses 100–500 user bersamaan.

📖 Target Performa

MetrikTargetAlat Ukur
Concurrent user≥ 500Locust
p95 Latency< 2 detikLocust
Failure Rate< 1%Locust
RPS (Request/sec)StabilLocust

🔍 Langkah Praktikum

  1. Install Locust

    pip install locust

    Jika belum punya Python: download dari python.org.

  2. Buat File locustfile.py

    Simpan di root proyek C:\DEVELOPMENT\Laravel\silacak-project\silacak\locustfile.py:

    from locust import HttpUser, task, between

class PenggunaSiLacak(HttpUser):
    wait_time = between(1, 3)

    def on_start(self):
        """Login sekali di awal sesi"""
        response = self.client.post("/login", {
            "email": "admin@silacak.test",
            "password": "password",
        })
        if response.status_code != 200 and response.status_code != 302:
            print(f"Login gagal: {response.status_code}")

    @task(5)
    def lihat_dashboard(self):
        self.client.get("/dashboard", name="/dashboard")

    @task(3)
    def lihat_daftar_resi(self):
        self.client.get("/resi", name="/resi")

    @task(2)
    def lacak_resi(self):
        self.client.get("/lacak?nomor_resi=SLC-20260929-0001", name="/lacak")

    @task(1)
    def cek_tarif(self):
        self.client.get("/tarif", name="/tarif")

    @task(1)
    def filter_resi(self):
        self.client.get("/resi?status=transit", name="/resi?status=")

  3. Jalankan Locust

    locust -f locustfile.py --host=http://localhost:8000

    Buka browser: http://localhost:8089

  4. Konfigurasi Skenario Beban

    Di form Locust:

    • Number of users: 100
    • Spawn rate: 10 users/detik
    • Host: http://localhost:8000

    Klik Start swarming.

  5. Amati Metrik (5 Menit)

    Perhatikan di dashboard Locust:

    MetrikNilai TargetInterpretasi
    RPSStabilJika turun = server kewalahan
    P95 Latency< 2000 msJika naik = query lambat
    Failure Rate< 1%Jika naik = server crash

  6. Uji Bertahap (Naikkan Beban)

    UserHasilKesimpulan
    50p95 = 300 msSehat
    100p95 = 800 msSehat
    200p95 = 1500 msWarning
    500p95 = 3500 ms, error 5%Titik patah

  7. Simpan Screenshot & Report

    Screenshot dashboard Locust. Simpan sebagai:

    • bukti-praktikum/p4-locust-100-users.png
    • bukti-praktikum/p4-locust-500-users.png

    Klik tab Download Data → Download Report (HTML) untuk bukti lengkap.

✅ Output yang Diharapkan
  • Report HTML Locust dengan grafik RPS, latency, dan failure rate
  • Kesimpulan: kapasitas maksimal server lokal
  • Rekomendasi optimasi jika p95 > 2 detik
⚠️ Tips Jalankan php artisan serve di terminal terpisah. Untuk beban > 200 user, gunakan php artisan serve --workers=4 atau setup Nginx + PHP-FPM.

P5 Alert Notification — Sentry

Unit Kompetensi
J.620100.044.01
Durasi
45 menit
Tingkat
Menengah

🎯 Tujuan

Mengintegrasikan Sentry untuk monitoring error real-time. Setiap error di aplikasi akan dikirim notifikasi ke dashboard Sentry + email/Slack.

📖 Alert Buruk vs Alert Informatif

❌ Alert Buruk "Error terjadi pada sistem!" — tidak ada konteks
✅ Alert Informatif (Sentry) "Galat simpan resi — user: admin@silacak.test — waktu: 14:32 WIB — trace: /logs/err-9912.log — IP: 10.0.0.5 — stack trace lengkap"

🔍 Langkah Praktikum

  1. Daftar Akun Sentry (Gratis)

    1. Buka https://sentry.io/signup/
    2. Daftar dengan email
    3. Buat project baru: Laravel
    4. Copy DSN (format: https://xxx@xxx.ingest.sentry.io/xxx)

  2. Install Package Sentry

    composer require sentry/sentry-laravel

  3. Konfigurasi DSN via Artisan

    Cara termudah — pakai perintah artisan dengan DSN kamu:

    php artisan sentry:publish --dsn=https://xxx@xxx.ingest.sentry.io/xxx

    Perintah ini akan:

    • Membuat file config/sentry.php
    • Menambahkan SENTRY_LARAVEL_DSN ke .env

  4. Edit bootstrap/app.php untuk Exception Handling

    Tambahkan handler Sentry:

    <?php

use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Sentry\Laravel\Integration;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware) {
        //
    })
    ->withExceptions(function (Exceptions $exceptions) {
        Integration::handles($exceptions);  // ← TAMBAHKAN
    })->create();

  5. Konfigurasi Log Channel (Opsional)

  2. Isi Controller

    Buka app\Http\Controllers\MonitoringController.php:

    <?php

namespace App\Http\Controllers;

use App\Models\Resi;
use Illuminate\Support\Facades\DB;

class MonitoringController extends Controller
{
    public function index()
    {
        return view('monitoring.index', [
            'resources' => $this->getResourceMetrics(),
            'database' => $this->getDatabaseMetrics(),
            'application' => $this->getApplicationMetrics(),
        ]);
    }

    private function getResourceMetrics(): array
    {
        $diskTotal = disk_total_space(base_path());
        $diskFree = disk_free_space(base_path());
        $diskUsed = $diskTotal - $diskFree;

        return [
            'php_version' => PHP_VERSION,
            'laravel_version' => app()->version(),
            'os' => php_uname('s') . ' ' . php_uname('r'),
            'memory_limit' => ini_get('memory_limit'),
            'memory_usage' => round(memory_get_usage() / 1024 / 1024, 2) . ' MB',
            'memory_peak' => round(memory_get_peak_usage() / 1024 / 1024, 2) . ' MB',
            'disk_total' => round($diskTotal / 1024 / 1024 / 1024, 2) . ' GB',
            'disk_used' => round($diskUsed / 1024 / 1024 / 1024, 2) . ' GB',
            'disk_free' => round($diskFree / 1024 / 1024 / 1024, 2) . ' GB',
            'disk_percent' => round(($diskUsed / $diskTotal) * 100, 2),
        ];
    }

    private function getDatabaseMetrics(): array
    {
        $start = microtime(true);

        try {
            DB::select('SELECT 1');
            $latency = round((microtime(true) - $start) * 1000, 2);
            $status = 'OK';
        } catch (\Throwable $e) {
            $latency = null;
            $status = 'ERROR: ' . $e->getMessage();
        }

        return [
            'connection' => config('database.default'),
            'database' => config('database.connections.mysql.database'),
            'latency' => $latency,
            'status' => $status,
            'total_resi' => Resi::count(),
            'resi_hari_ini' => Resi::whereDate('created_at', today())->count(),
            'table_size' => $this->getDatabaseSize(),
        ];
    }

    private function getDatabaseSize(): string
    {
        try {
            $result = DB::select("
                SELECT ROUND(SUM(data_length + index_length) / 1024 / 1024, 2) AS size_mb
                FROM information_schema.tables
                WHERE table_schema = ?
            ", [config('database.connections.mysql.database')]);

            return ($result[0]->size_mb ?? 0) . ' MB';
        } catch (\Throwable $e) {
            return 'N/A';
        }
    }

    private function getApplicationMetrics(): array
    {
        return [
            'cache_driver' => config('cache.default'),
            'session_driver' => config('session.driver'),
            'queue_driver' => config('queue.default'),
            'app_env' => config('app.env'),
            'app_debug' => config('app.debug') ? 'ON' : 'OFF',
            'timezone' => config('app.timezone'),
        ];
    }
}

P8 Perencanaan DWDM — Link Budget Jakarta–Cikarang

Unit Kompetensi
J.612000.019.01
Durasi
60 menit
Tingkat
Sulit

🎯 Tujuan

Menghitung link budget DWDM (Dense Wavelength Division Multiplexing) untuk koneksi antara DC Jakarta dan DRC Cikarang, serta menentukan kelayakan link.

📖 Konsep DWDM

DWDM = teknologi multiplexing yang memungkinkan banyak "warna" cahaya (wavelength) lewat dalam 1 kabel fiber optik.

  • 1 kanal DWDM = 1 warna = 10 Gbps
  • Butuh 5 kanal = butuh 5 warna berbeda dalam 1 kabel

📊 Data dari Studi Kasus

ParameterNilai
Tx Power0 dBm
Rx Sensitivity−24 dBm
Redaman fiber0,25 dB/km
Jarak Jakarta–Cikarang45 km
Mux + Demux2,5 + 2,5 = 5 dB
Konektor4 × 0,5 dB = 2 dB
Splice (tiap 2 km)@0,1 dB
Margin3 dB
Kebutuhan kanal3 × 10 Gbps + 2 cadangan = 5 kanal

🔍 Langkah Praktikum

  1. Buat Script Kalkulator DWDM

    Buat file hitung-dwdm.php di root proyek:

    <?php
/**
 * Kalkulator Link Budget DWDM
 * Jakarta (DC) → Cikarang (DRC)
 */

echo "======================================================\n";
echo "  KALKULATOR LINK BUDGET DWDM\n";
echo "  Jakarta (DC) → Cikarang (DRC)\n";
echo "======================================================\n\n";

// ============ PARAMETER ============
$txPower        = 0;
$rxSensitivity  = -24;
$fiberLossPerKm = 0.25;
$jarak          = 45;
$muxLoss        = 2.5;
$demuxLoss      = 2.5;
$konektor       = 4;
$konektorLoss   = 0.5;
$margin         = 3;
$splicePerKm    = 2;
$spliceLoss     = 0.1;
$kapasitasKanal = 10;
$kanalUtama     = 3;
$kanalCadangan  = 2;

// ============ PERHITUNGAN ============
echo "📐 PERHITUNGAN LINK BUDGET\n";
echo str_repeat("-", 55) . "\n";

$redamanFiber = $jarak * $fiberLossPerKm;
printf("1. Redaman Fiber       : %d km × %.2f dB/km = %.2f dB\n",
    $jarak, $fiberLossPerKm, $redamanFiber);

$jumlahSplice = floor($jarak / $splicePerKm);
$redamanSplice = $jumlahSplice * $spliceLoss;
printf("2. Jumlah Splice       : %d km / %d km = %d titik\n",
    $jarak, $splicePerKm, $jumlahSplice);
printf("   Redaman Splice      : %d × %.2f dB = %.2f dB\n",
    $jumlahSplice, $spliceLoss, $redamanSplice);

$totalMuxDemux = $muxLoss + $demuxLoss;
printf("3. Mux + Demux         : %.2f + %.2f = %.2f dB\n",
    $muxLoss, $demuxLoss, $totalMuxDemux);

$totalKonektor = $konektor * $konektorLoss;
printf("4. Konektor            : %d × %.2f dB = %.2f dB\n",
    $konektor, $konektorLoss, $totalKonektor);

printf("5. Margin              : %.2f dB\n", $margin);

$totalRedaman = $redamanFiber + $redamanSplice + $totalMuxDemux + $totalKonektor + $margin;
printf("\n   TOTAL REDAMAN       : %.2f dB\n", $totalRedaman);

$rxPower = $txPower - $totalRedaman;
printf("   Rx Power            : %.2f dBm - %.2f dB = %.2f dBm\n",
    $txPower, $totalRedaman, $rxPower);

$marginTersisa = $rxPower - $rxSensitivity;
printf("   Margin Tersisa      : %.2f dBm - (%.2f dBm) = %.2f dB\n",
    $rxPower, $rxSensitivity, $marginTersisa);

// ============ KESIMPULAN ============
echo "\n📊 KESIMPULAN LINK\n";
echo str_repeat("-", 55) . "\n";

if ($rxPower >= $rxSensitivity) {
    echo "✅ LINK LAYAK\n";
    printf("   Sinyal diterima: %.2f dBm ≥ Sensitivitas: %.2f dBm\n",
        $rxPower, $rxSensitivity);
    printf("   Margin tersisa: %.2f dB\n", $marginTersisa);
} else {
    echo "❌ LINK TIDAK LAYAK\n";
    printf("   Sinyal diterima: %.2f dBm < Sensitivitas: %.2f dBm\n",
        $rxPower, $rxSensitivity);
    printf("   Kekurangan: %.2f dB\n", abs($marginTersisa));
}

// ============ KANAL DWDM ============
echo "\n📡 PERENCANAAN KANAL DWDM\n";
echo str_repeat("-", 55) . "\n";

$totalKanal = $kanalUtama + $kanalCadangan;
printf("Kanal Utama    : %d × %d Gbps\n", $kanalUtama, $kapasitasKanal);
printf("Kanal Cadangan : %d × %d Gbps\n", $kanalCadangan, $kapasitasKanal);
printf("Total Kanal    : %d kanal\n", $totalKanal);
printf("Total Kapasitas: %d Gbps\n", $totalKanal * $kapasitasKanal);

echo "\n📋 Alokasi Wavelength (Channel Spacing 100 GHz / 0.8 nm)\n";
echo str_repeat("-", 55) . "\n";

$wavelengthStart = 1550.00;
for ($i = 1; $i <= $totalKanal; $i++) {
    $wavelength = $wavelengthStart + (($i - 1) * 0.8);
    $tipe = $i <= $kanalUtama ? 'Utama' : 'Cadangan';
    printf("  Kanal %d : %.2f nm (%s)\n", $i, $wavelength, $tipe);
}

// ============ RISIKO ============
echo "\n⚠️  CATATAN RISIKO\n";
echo str_repeat("-", 55) . "\n";

if ($marginTersisa < 2) {
    echo "Margin tersisa sangat tipis (< 2 dB). Berisiko saat:\n";
    echo "  - Suhu kabel berubah ekstrem\n";
    echo "  - Konektor kotor / aging\n";
    echo "  - Fiber menua\n";
    echo "\nREKOMENDASI:\n";
    echo "  - Tambahkan EDFA (Erbium-Doped Fiber Amplifier)\n";
    echo "  - Perbaiki kualitas konektor (gunakan UPC/APC)\n";
    echo "  - Pertimbangkan repeater di tengah jalur\n";
} elseif ($marginTersisa < 5) {
    echo "Margin tersisa cukup, namun tetap pantau kualitas link.\n";
} else {
    echo "Margin tersisa aman untuk operasional jangka panjang.\n";
}

echo "\n======================================================\n";
echo "  SELESAI\n";
echo "======================================================\n";

  2. Jalankan Script
